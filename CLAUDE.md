# personalities — repo guide for Claude Code

This repo ships interactive personalities (chat-register skills) for Claude
Code. Six furry personalities (vulpine / feline / lion / tiger / wolf /
bunny) share a common base; four standalone ones (caveman / brief / igor /
reset) don't.

## Layout

```
personalities/
├── common/template.md                 # master SKILL.md template (TOKENS in {{double braces}})
├── species/<name>/                    # per-furry-species sources
│   ├── data.json                      # single-token values (NAME, SPECIES, COLLAR_NAME, ...)
│   ├── core.md                        # Core character section
│   ├── voice.md                       # Voice section bullets
│   ├── heat.md                        # Heat-section cues
│   ├── good-boy.md                    # Good-boy reaction bullets
│   ├── collar.md                      # Collar reaction bullets
│   ├── praise.md                      # Praise vocabulary bullets
│   └── examples.md                    # Example exchanges
├── scripts/
│   ├── render-furry-skills.py         # the renderer
│   └── render-furry-skills.sh         # thin shell wrapper
└── skills/
    ├── <furry-name>/
    │   ├── SKILL.md                   # GENERATED by the renderer — checked in
    │   └── memory/                    # NOT touched by the renderer
    │       ├── repos.md               # repo log
    │       └── <species>-brain.md     # personality journal
    ├── caveman/SKILL.md               # standalone, hand-edited
    ├── brief/SKILL.md                 # standalone
    ├── igor/SKILL.md                  # standalone
    └── reset/SKILL.md                 # standalone
```

## Editing workflow

### To change something **shared across all six furry personalities**

Edit `common/template.md` and re-render:

```bash
./scripts/render-furry-skills.sh
git diff skills/*/SKILL.md         # eyeball the spread
git add common/template.md skills/*/SKILL.md
git commit -m "common: <what changed>"
```

The renderer overwrites `skills/<name>/SKILL.md` for the six furry
personalities. The four standalone skills are not touched.

### To change something **specific to one species**

Edit the appropriate file under `species/<name>/`:

| Want to change … | Edit |
|---|---|
| The species blurb in the frontmatter description | `data.json → DESCRIPTION_BLURB` |
| The collar size / extra collar lore | `data.json → COLLAR_SIZE` / `COLLAR_DESCRIPTION_EXTRA` |
| The species emoji | `data.json → SPECIES_EMOJI` |
| The diminutive (foxxie / leo / wolfie / ...) | `data.json → BEST_DIMINUTIVE` |
| The Core character lore paragraph | `species/<name>/core.md` |
| Action asterisks, vocab, sounds, sound-rules | `species/<name>/voice.md` |
| Heat-section cues + the "use the X deliberately" note | `species/<name>/heat.md` |
| The 4 bullets in "Good boy" section | `species/<name>/good-boy.md` |
| The species-specific collar reaction bullets | `species/<name>/collar.md` |
| The species-fit praise vocabulary bullets | `species/<name>/praise.md` |
| The example exchanges | `species/<name>/examples.md` |
| The body-parts-allowed list in Hard boundaries | `data.json → BODY_PARTS_LIST` |

Then re-render the same way.

### To add a **seventh furry personality**

1. Add the name to `SPECIES` in `scripts/render-furry-skills.py`.
2. Create `species/<new-name>/` with `data.json` + the 7 section files
   (copy from any existing species and adapt).
3. Create `skills/<new-name>/memory/{repos.md, <name>-brain.md}` with starter content.
4. Run `./scripts/render-furry-skills.sh` — it will create
   `skills/<new-name>/SKILL.md`.
5. Update `README.md` table.
6. Commit + push.

### What the renderer does

For each of the six furry species:

1. Reads `species/<name>/data.json` for single-token values.
2. Reads each `species/<name>/<section>.md` and stuffs its content into the
   matching `{{SECTION}}` token (e.g. `core.md` → `{{CORE_CHARACTER}}`).
3. Substitutes every `{{TOKEN}}` in `common/template.md` with the value.
4. Writes `skills/<name>/SKILL.md`.
5. Scans the output for any unsubstituted `{{TOKEN}}` and exits non-zero if
   any are found — that catches missing keys early.

The renderer is **idempotent and overwrite-safe**. Running it twice with no
source changes produces identical output. It does not touch `memory/` files
or any non-furry skill.

## Why generated SKILL.mds are checked in

Plugin install reads from the repo, not the source tree. So
`skills/<name>/SKILL.md` must be the rendered, ready-to-use form. Editing
the generated SKILL.md directly is **not** the workflow — your changes will
be overwritten on the next render. Edit the source (template or species
files), re-render, commit both.

## Hard rule for Claude

If you're working on this repo and you find yourself about to edit a
furry-personality `skills/<name>/SKILL.md` directly: **stop.** Edit the
source under `common/` or `species/<name>/` instead, then re-render. The
only `SKILL.md` files safe to edit by hand are the four standalone ones
(`caveman` / `brief` / `igor` / `reset`).
